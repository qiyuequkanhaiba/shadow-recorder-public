# v0.1.10 Release And Chinese README Design

## Goal

Publish the existing, manually smoke-tested Windows x64 installers as the
public `v0.1.10` GitHub Release, and provide a Chinese README without changing
application behavior or rebuilding the installers.

## Documentation

- Keep `README.md` as the English entry point.
- Add `README.zh-CN.md` as a complete Chinese counterpart covering scope,
  privacy, Windows build steps, installer verification, documentation,
  security, license, and ReqCase identifiers.
- Add reciprocal language links near the top of both README files.
- Preserve the existing warning: v0.1.10 predates the current default that
  requires explicit opt-in for semantic plaintext capture.

## Release Assets

The release assets are the existing files, copied directly from the local
release directory:

- `ShadowRecorder-Setup-0.1.10-x64.exe`
- `ShadowRecorder-0.1.10-x64.msi`
- `SHA256SUMS.txt`
- `v0.1.10-artifact-attestation.md`
- exact bundled FFmpeg license and notice files, when FFmpeg is present

No installer is rebuilt, modified, or committed to Git.

## Publication Gate

Before public release:

1. Recalculate SHA-256 values from the exact upload candidates and compare
   them with the attestation.
2. Verify Authenticode status using an available PE-signature verifier and
   record the actual result. Do not imply that an unsigned or unverifiable
   installer is signed.
3. Inspect the installer contents and build material to identify whether
   FFmpeg is bundled. If bundled, attach the exact associated license and
   notice files and record version, source URL, and archive checksum only when
   supported by evidence.
4. Complete the attestation and write release notes that include the privacy
   version boundary and checksum-verification instructions.
5. Create a GitHub Draft Release for the existing `v0.1.10` tag, upload the
   validated assets, review the rendered result, then publish it.

If signature or FFmpeg provenance cannot be verified, report that status
truthfully. If the required FFmpeg license material cannot be recovered, stop
before publishing rather than release an incompletely attributed binary.

## Verification

- Run the repository public-boundary and release-metadata audits after the
  README and attestation updates.
- Run Gitleaks and `git diff --check`.
- Confirm the GitHub Release is public, targets `v0.1.10`, has all expected
  assets, and displays the privacy warning.
