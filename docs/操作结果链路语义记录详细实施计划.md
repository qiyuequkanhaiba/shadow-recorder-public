## 1. 计划目标

现有实现已经能回答“用户在什么时间、什么窗口、什么控件上做了什么”，但仍不能稳定回答：

1. 操作前控件或页面是什么状态。
2. 操作后软件发生了什么可观察变化。
3. 哪些原始事件、截图和视频片段支持这个结论。
4. 未观测到结果时，系统是否诚实标记为未完成，而不是根据动作标题推测成功。

本计划将记录模型从单一 `StepRecord` 升级为：

```text
用户操作 OperationAction
    -> 状态迁移 StateTransition
    -> 操作结果 OperationOutcome
    -> 证据关系 OperationEvidence
    -> 用户可读记录 TestSessionOperationRecord
```

目标主句示例：

```text
单击按钮“保存” -> “保存成功”提示出现，耗时 420ms
勾选“启用同步” -> 开关状态由“关闭”变为“开启”，耗时 86ms
单击按钮“提交” -> 3 秒内未观测到明确结果
```

坐标、窗口句柄和原始 UIA 属性保留为技术证据及降级信息，不再作为正常记录的主要内容。

## 2. 当前基线与实施边界

### 2.1 已有能力，继续复用

- [x] 会话开始、暂停、恢复、停止及循环录屏。
- [x] `events.ndjson` 原始会话事件和统一墙钟时间轴。
- [x] 点击时按需 UIA 补全及 80ms 超时、失败熔断。
- [x] `StepBuilder`、`steps.ndjson`、L0-L4 步骤表达。
- [x] 键盘摘要、快捷键、剪贴板邻近关联，默认不记录输入明文。
- [x] 缺陷标记、视频时间窗、截图和缺陷包导出。
- [x] 步骤人工编辑和业务别名。
- [x] 记录与回顾页、语义步骤时间线和主题切换基础能力。

### 2.2 已确认缺口

- [ ] UIA 目前只有一次性快照，缺少持续属性和生命周期事件。
- [ ] 控件身份缺少 `runtimeId`、父级路径、窗口句柄、边界和 framework 等稳定定位信息。
- [ ] 缺少 Value、Toggle、Selection、ExpandCollapse、Range 等状态事实。
- [ ] `TestSessionStepRecord` 没有操作前后状态、完成信号、结果候选、耗时和证据边。
- [ ] 业务别名主要替换标题，尚未形成应用级语义画像和场景规则。
- [ ] 回顾页仍以“步骤”展示为主，无法区分已确认结果、候选结果、未完成和观测降级。

### 2.3 本轮明确不做

- 不整体搬入 qttimer 的 ETW、PresentMon、ONNX、Parquet 和多进程 Agent 架构。
- 不把 UIA、OCR 或视觉识别放到录屏主线程。
- 不承诺理解任意软件的业务正确性，只陈述可观察到的软件状态变化。
- 不用“高置信度”替代结果证据；没有证据时必须输出 `incomplete`。
- 不移除坐标兜底，但正常 UI 不突出坐标。
- 不默认保存输入明文，密码值在任何配置下都不记录。

## 4. 目标架构与数据流

```text
输入 Hook / 窗口事件
        |
        +--------------------------+
        |                          |
        v                          v
原始会话事件 events.ndjson     UIA Observer（目标进程内有限订阅）
                                   |
                                   v
                         semantic-events.ndjson
                                   |
                     +-------------+-------------+
                     |                           |
                     v                           v
              State Cache                Artifact / Video Index
                     |                           |
                     +-------------+-------------+
                                   |
                                   v
                         Operation Builder
                 动作关联 -> 状态迁移 -> 结果选择
                                   |
                     +-------------+-------------+
                     |                           |
                     v                           v
              operations.ndjson          operation-overrides.ndjson
                     |
                     +--> steps.ndjson（兼容投影）
                     +--> NAPI / Electron / React
                     +--> repro_steps.txt / 导出包
```

### 4.1 产物职责

| 产物 | 类型 | 职责 | 是否可重建 |
|---|---|---|---|
| `events.ndjson` | 原始事实 | 输入、窗口、会话、人工标记等低频事件 | 否 |
| `semantic-events.ndjson` | 原始事实 | UIA 属性、焦点、结构、窗口、弹窗等语义事件 | 否 |
| `operations.ndjson` | 派生视图 | 动作、结果、耗时、证据和置信度 | 是 |
| `operation-overrides.ndjson` | 人工事实 | 人工修改标题、结果选择、备注和忽略状态 | 否 |
| `steps.ndjson` | 兼容投影 | 为现有 API、导出和旧 UI 提供步骤视图 | 是 |

### 4.2 时间窗口纪律

- 目标关联窗口：输入发生前后约 `300ms`，以 runtimeId、控件路径和空间命中综合匹配。
- 结果观测窗口：从动作发生后开始，到下一次用户输入或最长 `3000ms` 结束。
- 明确完成信号可提前关闭结果窗口。
- 下一次输入到来时，先完成上一操作的结果选择，再建立新操作。
- 未发现可解释状态迁移时写入 `incomplete`，不得根据按钮名称生成“保存成功”等结论。
- 所有阈值进入配置和诊断快照，Golden 数据用于后续校准。

## 5. 核心数据契约

以下字段为实施基线。最终 Rust 和 TypeScript 类型名应保持一致，序列化统一使用 `camelCase`。

### 5.1 `UiElementIdentity`

```json
{
  "runtimeId": [42, 7, 19],
  "processId": 1234,
  "windowHwnd": "0x000A12BC",
  "name": "保存",
  "automationId": "btnSave",
  "controlType": "Button",
  "localizedControlType": "按钮",
  "className": "Button",
  "frameworkId": "WPF",
  "parentPath": [
    { "controlType": "Window", "name": "订单编辑" },
    { "controlType": "Pane", "automationId": "editorPane" }
  ],
  "boundingRect": { "left": 100, "top": 80, "width": 120, "height": 32 }
}
```

身份匹配优先级：`runtimeId` > AutomationId 与父级路径 > Name 与 ControlType 与父级路径 > 空间命中 > 坐标兜底。

### 5.2 `UiStateSnapshot`

```json
{
  "snapshotId": "state-...",
  "capturedAtMs": 0,
  "element": {},
  "isEnabled": true,
  "hasKeyboardFocus": false,
  "isOffscreen": false,
  "valueLength": 8,
  "valueFingerprint": null,
  "toggleState": "on",
  "selectionState": "selected",
  "expandCollapseState": "expanded",
  "rangeValue": 35.0,
  "privacyClass": "text-length-only",
  "source": "uia-property-event"
}
```

约束：

- 文本默认只保存长度；`valueFingerprint` 第一阶段保持 `null`。
- 密码控件不保存值、长度、指纹和候选文本。
- 数值型 RangeValue 可记录数值，但必须受隐私分类和应用排除规则约束。
- 未支持的 Pattern 使用 `null`，不能用默认值伪装已观测状态。

### 5.3 `OperationAction`

```json
{
  "actionId": "action-...",
  "kind": "click",
  "occurredAtMs": 0,
  "endedAtMs": 0,
  "target": {},
  "stateBefore": {},
  "coordinate": { "x": 1203, "y": 456, "displayId": "..." },
  "sourceEventIds": ["evt-..."],
  "targetReasonCodes": ["runtime-id-match", "point-hit"],
  "confidence": {
    "target": 0.96,
    "temporal": 0.92,
    "overall": 0.94
  }
}
```

`kind` 首批支持：`click`、`doubleClick`、`rightClick`、`toggle`、`select`、`expand`、`collapse`、`typeSummary`、`shortcut`、`scroll`、`windowSwitch`、`manualMark`。

### 5.4 `OperationOutcome`

```json
{
  "outcomeId": "outcome-...",
  "status": "confirmed",
  "summary": "“保存成功”提示出现",
  "observedAtMs": 0,
  "latencyMs": 420,
  "primaryTransitionId": "transition-...",
  "candidateTransitionIds": ["transition-..."],
  "reasonCodes": ["popup-appeared", "name-match-success-term"],
  "confidence": {
    "temporal": 0.91,
    "identity": 0.84,
    "transition": 0.95,
    "evidence": 0.90,
    "overall": 0.90
  }
}
```

`status`：

- `confirmed`：存在唯一且证据充分的选中结果。
- `candidate`：存在合理候选，但证据不足以唯一确认。
- `ambiguous`：多个候选接近，系统不替用户选择。
- `incomplete`：结果窗口内没有可解释完成信号。
- `observerDegraded`：UIA 观测不可用或被熔断，无法判断结果。
- `legacyUnknown`：旧会话只有步骤，没有结果事实。

### 5.5 `OperationEvidence`

```json
{
  "evidenceId": "evidence-...",
  "kind": "stateTransition",
  "role": "supportsOutcome",
  "sourceId": "transition-...",
  "occurredAtMs": 0,
  "artifactRef": null,
  "videoRange": null,
  "reasonCode": "toggle-state-changed"
}
```

`kind`：`rawEvent`、`uiaSnapshot`、`stateTransition`、`screenshot`、`videoRange`、`manualNote`。  
`role`：`supportsTarget`、`supportsOutcome`、`context`、`contradicts`。

### 5.6 `TestSessionOperationRecord`

```json
{
  "schemaVersion": 1,
  "kind": "reqcase.test-session-operation",
  "operationId": "operation-...",
  "sessionId": "ts-...",
  "sequence": 12,
  "startedAtMs": 0,
  "endedAtMs": 0,
  "relativeMsFromSessionStart": 0,
  "action": {},
  "outcome": {},
  "completionCandidates": [],
  "transitions": [],
  "evidence": [],
  "title": "单击按钮“保存”",
  "resultSummary": "“保存成功”提示出现",
  "displaySummary": "单击按钮“保存” -> “保存成功”提示出现，耗时 420ms",
  "precisionLevel": "l3",
  "edited": false,
  "businessAlias": null
}
```

### 5.7 Reason Code 最小集合

| 分类 | Reason Code |
|---|---|
| 目标 | `runtime-id-match`、`automation-path-match`、`focus-match`、`point-hit`、`ancestor-semantic-match`、`coordinate-fallback` |
| 状态 | `value-length-changed`、`toggle-state-changed`、`selection-changed`、`expand-state-changed`、`range-value-changed`、`enabled-state-changed` |
| 生命周期 | `focus-changed`、`window-opened`、`window-closed`、`popup-appeared`、`dialog-appeared`、`structure-changed` |
| 结束 | `explicit-completion`、`next-input-closed-window`、`result-timeout`、`no-observable-change`、`multiple-candidates` |
| 降级 | `uia-timeout`、`uia-circuit-open`、`queue-overflow`、`observer-restarted`、`target-process-mismatch` |

Reason Code 是测试和诊断契约，不允许仅用自由文本替代。

## 6. 全局实施规则

### 6.1 兼容规则

1. 新会话同时生成 `operations.ndjson` 和 `steps.ndjson`。
2. `operations.ndjson` 是新 UI 和新导出的首选读取源。
3. `steps.ndjson` 是兼容投影，不再承载新状态字段。
4. 旧会话只有 `steps.ndjson` 时，在内存中映射为 `legacyUnknown` 操作，不自动改写原会话。
5. `get_test_session_steps`、现有 Electron IPC 和旧导出在 Release A 内不得删除。
6. 稳定 ID 基于会话 ID 和锚点事件 ID，禁止使用列表序号生成，以保证重建后人工修改仍能合并。

### 6.2 隐私规则

1. 密码控件值永不记录。
2. 普通文本默认仅记录长度。
3. 明文记录必须是单独的显式选择，不能复用普通“启用语义记录”开关。
4. 原始 UIA 事件写盘前统一经过 sanitizer，UI 和导出层不承担最后一道脱敏责任。
5. 截图和视频继续沿用现有隐私确认。
6. 日志不得输出 UIA 原始 Value、键盘字符或未脱敏事件 JSON。

### 6.3 线程和可靠性规则

1. UIA 在专用 MTA worker 中初始化、订阅和释放。
2. UIA 回调只复制必要字段并入有界队列，不遍历 UI 树、不写文件、不调用 React/Electron。
3. Hook 回调不等待 UIA 结果。
4. 队列满时按策略丢弃低价值重复事件，并记录计数器，不能阻塞录屏。
5. UIA 超时、worker 崩溃、目标进程退出均必须可恢复。
6. 录屏、视频环和会话停止优先级高于语义记录。

### 6.4 UI 规则

1. 产品页面继续称为“记录与回顾”，不使用“缺陷证据”作为页面名称。
2. 保留语义步骤时间线最外层容器；时间线节点内部不再嵌套胶囊卡片。
3. 单个节点只使用一个表面层级，状态仅使用小型状态标识，不把全部字段做成徽章。
4. 信息顺序固定为：时间和序号 -> 操作主句 -> 结果主句 -> 关键上下文 -> 折叠技术详情。
5. 坐标、locator、原始事件、置信度分项、截图和视频区间进入折叠详情。
6. 问题标记区域支持折叠/展开，并保持键盘可操作和 `aria-expanded`。
7. 布局使用 `minmax(0, 1fr)`、容器查询或断点自动适应窗口，不设置只适合固定宽度的居中卡片。
8. 所有颜色、边框、阴影和圆角使用现有主题 token，确保跟随整体风格设置。
