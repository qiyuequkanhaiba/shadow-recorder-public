## 1. 背景与结论

### 1.1 业务目标

帮助**测试工程师在记录缺陷 / Bug 时，快捷提供有效证据和可复现操作步骤**。

交付物不是“更全的监控台”，而是：

1. **短视频片段**（问题前后时间窗，直观）
2. **可读复现步骤**（可贴缺陷单）
3. **关键点击截图**（快速扫一眼）
4. **环境与时间元数据**（可追溯）

### 1.2 核心结论（已拍板）

| 议题 | 结论 |
|------|------|
| 主证据载体 | **循环录屏视频**（已有能力继续打磨） |
| 步骤来源 | **输入事件时间轴 + 按需 UIA 语义补全**，不是从整段视频反推操作 |
| 语义精度目标 | **L2 为主**（控件级可读步骤）；**L3（输入摘要）为第二阶段** |
| 键盘策略 | **默认只记摘要，不落明文** |
| UIA 失败 | **降级为坐标 + 窗口标题**，绝不阻断录屏 |
| 步骤聚合时机 | **会话结束 / 标记缺陷后离线聚合即可**（准实时可用，非逐帧实时） |
| 点击快照 webp | **默认继续开启** |
| 纯录屏提取操作流 | **不做主方案**；OCR/视觉仅可作远期补强 |
| “只保留录像” | 可作为更窄 MVP，但**本方案正式目标是录像 + 步骤 + 缺陷包** |

### 1.3 与 qttimer 的关系

参考 qttimer 的价值点：

- 输入事件带控件快照（`ElementFromPoint` / `FocusedElement`）
- 统一时间线事件模型
- 操作切分与动作描述（可读标签）
- UIA 超时与失败降级

**明确不迁移：**

- ETW / PresentMon / 响应时延闭环
- 全程高频 UIA 树订阅
- .NET Agent 多进程架构 / Parquet 主存储
- “测量 UI 响应时间”产品目标

一句话差异：

> qttimer 回答“点击到页面稳定花了多少毫秒”；  
> Shadow Recorder 回答“这段录屏里用户按什么顺序做了什么，并一键交给缺陷单”。

## 2. 问题与现状

### 2.1 当前已具备

- 会话生命周期：start / pause / resume / stop
- 循环视频：`FfmpegLoopRuntime` + segment 环 + 预算告警
- 事件侧带：`events.ndjson`（生命周期、`step_captured`、窗口事件、剪贴板等）
- 鼠标输入：`WH_MOUSE_LL` + Raw Input 自动切换
- 点击触发窗口截图 → `StepData`（坐标、进程、窗口标题、webp）
- 回放：事件时间 → segment 映射 seek（墙钟对齐路径已存在）
- 证据导出骨架（会话级，非缺陷专用包）

### 2.2 当前缺口（相对本目标）

| 缺口 | 影响 |
|------|------|
| 无稳定 L2 控件语义 | 步骤停留在坐标/原始 action，难直接贴缺陷单 |
| 无 `StepBuilder` / `steps.ndjson` | 原始事件未聚合成复现步骤流 |
| 无键盘摘要 | 表单路径信息不足（二期） |
| 无“标记缺陷”一等入口 | 缺少问题锚点与时间窗裁剪 |
| 导出偏整会话 | 测试要的是短 clip + 步骤文本，不是整场 40 分钟素材 |
| 无 `repro_steps.txt` / 一键复制 | 仍需人工整理文字步骤 |

### 2.3 精度分级定义

| 级别 | 示例 | 本方案阶段 |
|------|------|------------|
| L0 | 在 (1203,456) 左键点击 | 降级兜底 |
| L1 | 在窗口「订单管理」点击 | 降级兜底 |
| L2 | 点击按钮「新建订单」 | **Phase A 主目标** |
| L3 | 在「客户名称」输入 8 个字符 | **Phase B** |
| L4 | 业务别名「创建客户」 | 远期可选 |

## 3. 目标与非目标

### 3.1 目标

1. 在**不中断循环录屏**的前提下，采集可对齐视频的操作时间轴。
2. 按需 UIA 补全控件身份，生成 **L2 可读步骤**；失败自动 L0/L1。
3. 支持测试 **标记缺陷**，自动截取前后时间窗证据。
4. 停止或标记后**离线聚合**步骤，并在数十秒内可预览/导出。
5. 一键产出 **缺陷证据包** 与 **可粘贴复现步骤文本**。
6. 步骤与视频 **同一墙钟时间轴**，seek 误差满足缺陷场景（见验收）。

### 3.2 非目标

1. 帧级 / 毫秒级音画专业同步。
2. 从整段 mp4 端到端“AI 还原操作流”作为主链。
3. 全量键鼠原始流持久化、输入明文落盘。
4. 全程 UIA 树订阅、ETW、PresentMon。
5. 自动判定“这是不是 bug”（结果态由测试标记）。
6. 一次做完跨产品业务语义画像（L4）。

---

## 4. 已确认产品决策

1. **L2 为主，L3 为第二阶段。**
2. **键盘默认只记摘要，不落明文。**
3. **UIA 失败降级为坐标 + 窗口标题，不阻断录制。**
4. **允许会话结束后离线聚合**；但标记/停止后须**准实时可用**（同步跑一遍聚合即可）。
5. **点击快照 webp 默认开启。**
6. **录像必须保留**；步骤是缺陷交接的加速器，不替代短视频直观性。
7. **对齐靠统一时间戳**，不靠从画面猜点击时刻。

## 5. 总体架构

### 5.1 分层

```text
┌──────────────────────────────────────────────────────────────┐
│ Electron / React                                             │
│  标记缺陷 · 步骤列表 · seek 视频 · 复制步骤 · 导出缺陷包       │
└──────────────────────────────▲───────────────────────────────┘
                               │ NAPI / IPC
┌──────────────────────────────┴───────────────────────────────┐
│ Session Runtime（已有，增量）                                  │
│  video_ring / ffmpeg_loop / system_events / events.ndjson    │
└──────▲───────────────────▲───────────────────▲───────────────┘
       │                   │                   │
 Input Capture      UIA Enricher          Step Builder
 鼠标(+二期键盘)     按需·独立线程·超时      离线聚合 → steps.ndjson
 标准化 TimelineEvent  best-effort          Defect Packager
```

### 5.2 三条并行管道（同一会话时钟）

| 管道 | 职责 | 产物 |
|------|------|------|
| Video | 循环录屏（主载体） | `video/segments/*.mp4` + stream 索引 |
| Raw Timeline | 原始事实事件 | `events.ndjson` |
| Semantic Steps | 可读复现步骤 | `steps.ndjson` + `repro_steps.txt`（导出时） |

### 5.3 时间对齐模型

```text
session.started_at_ms          （会话墙钟零点参考）
event/step.timestamp_ms        （输入发生时 SystemTime 墙钟）
segment.started_at_ms/ended    （ffmpeg run 墙钟 + 段内相对秒）

seek 偏移:
  offset_in_segment = clamp(step.timestamp_ms - segment.started_at_ms, 0, duration)
  global_playback   = segment.accumulated_start + offset_in_segment

推荐冗余字段:
  step.relative_ms_from_session_start = step.timestamp_ms - session.started_at_ms
```

**纪律：**

- 步骤时间戳 = **输入事件时间**，禁止用 UIA 完成时间覆盖。
- UIA 只丰富语义字段，不改时间轴。
- 暂停/恢复产生的时间间隙须在 segment 索引与 seek 逻辑中显式处理。

### 5.4 目标体验工作流

```text
1. 开始录制（循环视频 + 事件采集）
2. 正常测试；点击时尽力 UIA + 默认 webp 快照
3. 发现 bug →「标记缺陷」（可填期望/实际一句）
4. 可选再录 10–20 秒后停止，或立即停止
5. 离线 StepBuilder 聚合时间窗内步骤
6. 预览：复现步骤 + 关键截图 + 视频片段
7. 「复制步骤」贴缺陷单 / 「导出证据包」附件 zip
```

## 6. 数据采集设计

### 6.1 输入层（扩展现有 hooks / raw_input）

**Phase A**

| 事件 | 策略 |
|------|------|
| 左/右/中键、双击、滚轮 | 保留；标准化名称（如 `mouse_left_click`） |
| 坐标 | 物理 + 逻辑（DPI） |
| 窗口上下文 | 进程名、标题、hwnd、display_id |

**Phase B**

| 事件 | 策略 |
|------|------|
| 键盘 | `WH_KEYBOARD_LL`；功能键可记名；字符只记数量 |
| 快捷键 | Ctrl/Alt/Shift 组合摘要 |
| 密码框 | `is_password=true`，不记 value |

默认不持久化：全量 mousemove、全量 key down/up 明文流。

### 6.2 按需 UIA 补全（Phase A 核心）

**触发点：**

- 鼠标 click / double-click / right-click
- 前台切换 / 焦点变化（轻量）
- 标记缺陷时刻（可选补一次焦点控件）

**采集字段：**

- `control_name`, `automation_id`, `control_type`, `class_name`
- `framework_id`, `bounding_rect`, `is_enabled`, `is_password`
- `value_len`（可选，不明文）

**实现约束：**

- 独立工作线程 + **超时 80ms（建议 p95 目标 50ms）**
- 鼠标：`ElementFromPoint`，向上 6–8 层选取有 Name/AutomationId 的节点
- 键盘（二期）：`FocusedElement`
- 连续失败 N 次（建议 20）可熔断一段时间，避免拖垮会话
- 任何失败：**主录屏与事件写入不受影响**

### 6.3 系统事件（已有，继续复用）

- 前台 / 焦点 / 显示隐藏 / 标题变化（去抖）
- 剪贴板类型摘要（不明文）

### 6.4 点击快照

- 默认开启 webp（全图或沿用现有质量策略）
- 写入 session `artifacts/`，步骤通过 `artifact_refs` 引用
- 导出缺陷包时带上时间窗内截图

## 7. 步骤生成（StepBuilder）

### 7.1 职责

消费 `events.ndjson`（及内存事件缓冲），输出 `steps.ndjson`。

触发时机：

1. `stop_test_session`
2. `mark_defect` / 标记缺陷（对时间窗增量或全量重建）
3. 可选：手动“重新生成步骤”

### 7.2 Phase A 聚合规则

| 规则 | 输出示例 |
|------|----------|
| 单击 + UIA | 点击按钮「新建订单」 |
| 单击无 UIA | 在窗口「订单管理」点击 (x,y) |
| 双击 | 双击「订单-1001」 |
| 右键 | 右键「客户名称」 |
| 前台切换（去抖） | 切换到窗口「订单管理」 |
| 人工备注 / 标记缺陷 | 标记缺陷：保存后金额未刷新 |

去重参考（可借鉴 qttimer）：

- 约 120ms 内同区域 down/up 合并为一次点击
- 标题抖动去抖（沿用现有 system event 策略）

### 7.3 Phase B 增量规则

- 连续字符输入 → 单条输入摘要步骤
- 快捷键 → `使用快捷键 Ctrl+S`
- 剪贴板变更 + 邻近粘贴 → 粘贴摘要（类型级）

### 7.4 StepRecord 模型（建议）

```json
{
  "schema_version": 1,
  "kind": "reqcase.test-session-step",
  "step_id": "step-...",
  "session_id": "ts-...",
  "started_at_ms": 0,
  "ended_at_ms": 0,
  "relative_ms_from_session_start": 0,
  "step_type": "click",
  "title": "点击按钮「新建订单」",
  "summary": "在「订单管理」中点击【新建订单】",
  "process_name": "app.exe",
  "window_title": "订单管理",
  "control_name": "新建订单",
  "control_type": "Button",
  "automation_id": "btnNewOrder",
  "x": 1203,
  "y": 456,
  "display_id": "\\\\.\\DISPLAY1",
  "precision_level": "l2",
  "confidence": 0.86,
  "source_event_ids": ["evt-..."],
  "artifact_refs": ["artifacts/....webp"]
}
```

`precision_level`: `l0` | `l1` | `l2` | `l3`

### 7.5 复现步骤文本

导出 / 复制时生成 `repro_steps.txt`：

```text
环境: <os / app version if known>
会话: <session_id>
缺陷标记时间: <iso or ms>
时间窗: T-60s ~ T+20s（可配置）

复现步骤:
1. 切换到窗口「订单管理」
2. 点击按钮「新建订单」
3. 点击按钮「保存」
4. 【缺陷】保存后金额未刷新
```

## 8. 缺陷标记与证据包

### 8.1 标记缺陷（P0）

输入：

- `marked_at_ms`（默认 now）
- `note` / 期望 / 实际（可选短文本）
- `pre_window_seconds`（默认 60，可配置 30–180）
- `post_window_seconds`（默认 20）

行为：

1. 写入 timeline 事件 `defect_marked`
2. 锚定时间窗 `[marked - pre, marked + post]`
3. 触发 StepBuilder（窗内或全量后裁剪）
4. 索引窗内 video segments / 点击 artifacts
5. UI 进入缺陷预览态

### 8.2 缺陷包目录结构（P0）

```text
defect-{sessionShort}-{markMs}/
  repro_steps.txt
  summary.json
  steps.json
  events.snippet.ndjson      # 可选
  video/
    clip.mp4                 # 优先单文件；否则 segments + playlist 说明
    segments/                # 若暂不能无损拼接，保留窗内 segment 列表
  screenshots/
    01-....webp
  manifest.json
```

`summary.json` 最少包含：

- session_id, marked_at_ms, pre/post window
- target process / capture mode
- app/native version, os
- step_count, screenshot_count, video_bytes
- privacy flags（含键盘模式、是否含截图/视频）

### 8.3 与现有 EvidenceExport 关系

- **保留**现有会话级导出能力。
- **新增** `export_defect_pack`（或等价 IPC），默认走缺陷模板。
- 隐私确认沿用现有“含截图/视频需确认”逻辑。

## 12. 验收标准

### 12.1 时间对齐（必须）

1. 连续 10 次不同控件点击，步骤 seek 视频：  
   - **≥9/10** 落在对应操作前后 **0.5s** 内  
   - 全部不超过 **1s**  
2. 步骤时间戳不得系统性整体偏移（禁止用 UIA 完成时间）。  

### 12.2 语义精度（Phase A）

1. 在常见 Win32/WPF/主流桌面被测应用上：  
   - **≥80%** 点击步骤达到 L2（Name 或 AutomationId 或有意义 ControlType+上下文）  
2. UIA 失败时：  
   - 100% 仍有 L0/L1 步骤 + 时间戳 +（默认）截图  
3. 连续录制 1 小时：UIA 超时/失败不导致录屏中断或进程崩溃。  

### 12.3 缺陷工作流（必须，产品向）

1. 标记缺陷后 **60s 内**（常规会话体量）可预览：  
   - 可读复现步骤  
   - 时间窗内视频片段或 segment 集合  
   - 相关点击截图  
2. 一键复制步骤可直接粘贴缺陷管理系统。  
3. 导出 zip 可直接作为附件；开发无需打开录制器即可理解问题。  

### 12.4 隐私（必须）

1. 默认无键盘明文。  
2. 密码类控件不落 value。  
3. 含截图/视频导出需既有隐私确认。

| 项 | 预算 |
|----|------|
| UIA 单次 | 超时 80ms；失败放弃 |
| StepBuilder | 结束时批量，常规会话秒级内完成 |
| 额外 CPU | 相对纯录屏约 +1%～3% |
| 额外内存 | 约 +20～40MB |
| 磁盘 | steps.ndjson 远小于视频；webp 按现有策略 |

原则：**视频环是主链路；UIA/步骤 best-effort。**

---

## 14. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 弱 UIA 应用语义差 | L0/L1 + 截图 + 视频；不阻塞 |
| segment 边界时间误差 | 统一墙钟；验收 0.5s/1s；必要时校准 run start |
| 暂停导致 seek 错位 | 显式 gap 处理与测试用例 |
| 步骤过多难读 | 默认展示聚合步骤；原始事件进高级视图 |
| 导出包过大 | 默认时间窗 clip，非整会话 |
| 与 legacy StepData 双轨 | 新会话以 StepRecord 为准；legacy 兼容不扩展新语义 |

## 15. 明确不做的替代路线（避免返工）

| 路线 | 决策 | 原因 |
|------|------|------|
| 纯录屏 CV/VLM 提取操作流 | 否（主方案） | 低帧率/可关鼠标/无键盘痕迹；慢且难验收 |
| 只保留裸 mp4、无步骤无标记 | 否（本方案目标） | 偶现留证可以，缺陷交接不够快捷 |
| 整仓移植 qttimer | 否 | 栈不同、目标不同 |
| 实时逐步重 AI 推理 | 否 | 与离线聚合、本地快捷冲突 |

## 16. 建议开发顺序（执行清单）

1. **模型与落盘**：`StepRecord`、`steps.ndjson`、事件字段扩展（控件语义可选字段）  
2. **UIA enricher**：独立线程、超时、熔断、单测/手工矩阵  
3. **输入标准化**：hook 路径写入统一 timeline 字段  
4. **StepBuilder**：stop 后生成步骤；单元测试覆盖去重与降级文案  
5. **mark_defect**：时间窗 + 事件  
6. **导出缺陷包 + repro_steps.txt**  
7. **前端**：步骤侧带 seek、标记缺陷、复制/导出  
8. **验收脚本/手工用例**：对齐 12 章标准  
9. （Phase B）键盘摘要

## 17. 成功定义（一句话）

> 测试在循环录屏过程中一点「标记缺陷」，系统在一分钟内给出与视频对齐的 L2（尽力）复现步骤、关键截图和短视频证据包，并可一键复制步骤到缺陷单；UIA 失败时证据不断档，录屏永不被步骤链路拖垮。
